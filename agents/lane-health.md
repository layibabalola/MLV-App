## Tier-B lane-health contract
- Treat liveness as a multi-surface decision: adopted lease freshness, journal activity, heartbeat-marker evidence, and heartbeat-automation target validity are separate surfaces.
- Journal age is advisory only. A fresh journal cannot override a missing/stale/malformed adopted lease or an invalid heartbeat target. Missing leases remain advisory only for lanes that have not adopted lease gating.
- Codex, Sol, and `claude-review` are adopted lanes and must renew `health/leases/<lane>.json` with the exact lane, UTC ISO timestamp, and positive `leaseMinutes` before a sweep can report them LIVE. A missing adopted lease is DEGRADED, not perpetual `PENDING-ADOPTION`.
- Run `tools/coordination/validate-heartbeat-target.ps1` from CLI before trusting the 10-minute automation; ACTIVE registry state without a valid UUID target matching the current task is invalid.
- Heartbeat commands must not resolve coordination tooling relative to an arbitrary task checkout. Run `tools/coordination/run-lane-heartbeat.ps1` from a current target runtime, pass the canonical repo through `-RepoRoot`, and let companion tools resolve from `$PSScriptRoot`; detached or foreign-dirty main checkouts are data surfaces, not tool runtimes.
- Use `tools/coordination/sweep-lane-health.ps1` for machine-readable JSON health and preserve non-zero exit status for DEGRADED state. Do not whitelist crashes, weaken strict test exit handling, or infer hosted CI health from lane health.
- **There are two sweeps and they are different instruments.** `tools/coordination/sweep-lane-health.ps1` emits the machine-readable `lane-health.v3` JSON consumed by `run-lane-heartbeat.ps1`. `tools/coordination/board-health-sweep.ps1` writes the `health.log` line that every board liveness claim reads, and additionally emits the `watchhb:`, `nudge:`, `dispatch:`, `gap:` and `ckid:` tokens. The board sweep was promoted out of `.claude-state/coordination/dual-lane/health/` under SWEEP-CLASS-1: while it lived in a gitignored path `owner-of.ps1` returned `unknown`, `lane-commit` hard-blocked it, no gated range could contain it, and it had no tests. Do not reintroduce an implementation under `.claude-state/`; that path may hold at most a forwarding shim.
- **`tools/coordination/lane-health-classes.psd1` is the single authority for the lane-state class list and the DARK boundary**, and BOTH sweeps read it. The boundary is `min(leaseMinutes,30)+20`; the former second function `2 * leaseMinutes` is deleted, and with it the `EXPIRED` class, which existed only to name the interval between the two. The two agreed at exactly `leaseMinutes = 20` and disagreed everywhere else. Cite this file rather than restating the class list; a vocabulary restated in prose is a second authority waiting to drift.
- **A dispatch is executable only through a durable dispatch intent.** Before a hub ledger entry says `DISPATCHED`, create one `dual-lane-dispatch-intent.v1` JSON object per executable owner and run `py -3 tools/coordination/dispatch-queue.py submit --dual-lane-dir <canonical-dual-lane-dir> --intent-file <intent.json> --apply --json`. The command installs the intent first, validates the cited Fable SEQ and optional artifact hash, then upserts `queue.json` through `write-verified-json.ps1`. A crash between those writes is repaired by the next `board-health-sweep.ps1` run. Once materialized, the intent is a delivery receipt rather than a lifecycle lock: reconciliation matches the immutable card id plus `dispatchedSeq` and must never revert later hub-owned state, owner, priority, scope, or bookkeeping fields; a heal must also preserve monotonic `queue.json.updatedBySeq`. Do not hand-edit a prose dispatch and promise to add its card on a later turn: the sweep reports such entries as `dispatch-intents=PROSE-ONLY(...)` and raises `OVERALL=ATTENTION`; it never invents missing owner, priority, or scope from prose.
