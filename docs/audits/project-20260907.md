# Project audit — 7 September 2026

The project has useful product code, extensive regression infrastructure, and an
incomplete delivery recovery. Its immediate constraint is converting a selected
product change into a verified release without repeatedly reopening coordination.
Changing models alone will not repair that constraint.

This audit supplies a work-stream map and concrete amendments to the existing
recovery plan. It does not install new dispatch rules, replace the live hub,
authorize golden changes, or certify product performance.

## Findings, ranked by impact

**F01 — The current health metric can reward factory churn. Verified locally.**
`.claude-state/heartbeat/board-heartbeat.ps1:588` reads `git log --all`; lines
593–595 classify changes under `tools/` as product transitions. Its September 7
snapshot advertised 125 product transitions and an OK ratio. That number includes
unmerged branches and factory tools. It cannot measure delivered product progress.

At refreshed target `1a4f152d`, 3 of 79 non-merge commits since August 29 touch
`src/` or `platform/` (3.8%); since September 1, 2 of 73 (2.7%). These are source-touch
proxies, not accepted features. There has been real product work: at intake,
520 of 1,514 non-merge commits since June 1 touch those paths. These final figures
use a full reachable walk bucketed by committer epoch at explicit UTC midnight,
as the fleet's project spec requires. “Nothing was built”
would be inaccurate; recent effort is overwhelmingly diverted into the factory.
**Fix:** existing step 0.6 must replace the heartbeat's metric as well as gate the
dispatcher. Report accepted product PRs and release outcomes separately.

**F02 — The recovery is partially implemented, not operational. Verified locally.**
The old dispatch log contains 49 rows: factory 27, playback 14, unclassified 8,
product 0; Luna 29, Fable 20. This is the unattended log, not all manually launched
work. The 15 new product/playback cards pass the current local parity checker.
#77, #79 and #81 landed the hook/guard foundation, backlog, and editing dispatcher;
#80 landed during this audit. The marker `WORKSTREAM-LOOP-DISABLED` still exists.
The installed task targets `C:\mlvtmp\ws-driver\tools\coordination\Invoke-WorkstreamLoop.ps1`
at old checkout `55c486d4`, with no persisted track or editing arguments.
**Fix:** finish receipt-gated Phase 0; use the already-permitted manual wrapper for
independent product work meanwhile. Do not simply delete the marker.

**F03 — A valid card is not necessarily executable. Verified by source inspection.**
`Invoke-Workstream.ps1:302–313` checks scheduling state/track; selection at
352–378 does not enforce `queue.json.dependsOn`. The composer copies `DEPENDS_ON`
as prose. No writer for `dependencies.json` or `playCountersGpuReceipt` was found
in `tools/coordination` or `tests/coordination`, although the C2 acceptance card
requires those exact dispatcher exports. The 15-card parity check nevertheless
passes: it checks kind, scope, procedure and hash, not dependency execution.
**Fix:** typed prerequisites, deterministic artifact export, and no dispatch/token
reservation when inputs are absent. Add this bounded amendment before unattended
activation; do not ask a cheap worker to improvise missing inputs.

**F04 — Completion has competing authorities. Verified locally.**
The new plan defines done as merged plus verified target CI, uses PR review by
Sol, and says seats are retired. `agents/brokered-auto-closeout.md` still mandates
finalize on substantive edits; `closeout.config.json` requires a Claude ledger
review under one session allowlist, five acceptance surfaces, and no ordinary
linked sibling worktrees. The recovery deliberately leaves these paths unchanged
(plan lines 814–817). Isolated worktrees and an absolute no-sibling completion
condition cannot both be the universal steady state.
**Fix:** a separately reviewed contract amendment must state which actor performs
PR acceptance, exact work-block commit/cleanup, and global repository maintenance.
Preserve ownership, review, golden and production controls. Until that amendment
lands, report these statuses separately and honor an actual blocking gate.

**F05 — Low-cost execution is not currently configured as requested. Verified locally.**
`Invoke-Lane.ps1:105–109` assigns Luna high reasoning; its role is breadth recon.
Luna and Sol editing are explicitly refused; Haiku is absent from `ValidateSet`
(line 51). The plan's prose allows a Haiku hub, but that is not a supported Haiku
lane. A queue owner named Sonnet also does not make an old installed runtime launch
an editing Sonnet worker.
**Fix:** use Sonnet for bounded edits now and Luna for read-only verification.
Qualify Haiku and low-reasoning Luna on fixed tasks before changing the adapter.
Luna editing needs a reviewed equivalent containment mechanism, not removal of a
refusal. See the execution document for a staged, measured policy.

**F06 — The queue and continuation text lag delivered work. Verified locally.**
Queue cards `C2-TELEM-2` and `C2-PROV-1` remain dispatched, while #64 and #67 are
merged on GitHub. Their exact delivery must be reconciled by ancestry and artifact
coverage, not blindly re-executed or closed by title. The checkpoint says rev 29;
both inspected plan headers say v28. Twenty-six plan/register/prompt pairs match
after newline normalization; differing file byte sizes alone are not content drift.
**Fix:** idempotent reconciliation and one derived checkpoint; keep history as
evidence, not dispatch authority.

**F07 — Tests cover important pieces but can miss production wiring. Verified locally.**
At the audited target, required GitHub contexts are the two Repo Hygiene Python
jobs, Factory Bridge Regressions, Windows GUI Pilot, and Windows Product Oracles.
`Batch Compile` is not yet required. PR #82 contains a successful Batch Compile
check, but a green job on an open PR is not an installed required gate. Existing
tests isolate many policies; they do not prove every MainWindow/BatchRunner call.
The TLS verification bypass is still present despite green hosted checks.
**Fix:** preserve existing product oracles, add the full-app compile falsifier,
and cover real call sites plus failure behavior for each extracted policy.

**F08 — GPU acceptance needs provenance before another benchmark. Cross-checked
from prior analysis; runtime state needs a new measurement.**
The September 5 C2 precondition investigation found a June 20 DLL without the
async exports in the staged bachelor bundles. That explains how a “zero engagement”
result can measure an obsolete artifact instead of the candidate. This audit did
not inspect the present remote DLL. Revalidate it before dispatching a workload.
Also, synchronous-path hash agreement alone is insufficient: the standing output
policy requires an independently known-good build. A shared defect can make both
paths agree. The existing C2 card needs that distinction made executable.

**F09 — Startup cost and historical rules exceed a cheap worker's useful context.
Verified locally.** The six named surfaces total 317,793 bytes on disk; the
132,302-byte handoff includes history, so this is not a measured per-turn token
charge. The plan's future cap is 30,000 bytes using only the newest handoff block.
The 110 KB plan itself contains a long ratification history. Pinned-token checks
pass 144 assertions while the linked `docs/22-doc-fragmentation-policy.md` is
absent. String presence is not document-link validity or policy consistency.
**Fix:** restore/repair the missing policy link, move history out of startup,
retain mandatory rules, and compile only the chosen task's source/test pointers.

**F10 — Release and user purpose remain disconnected from factory success.
Verified locally / product acceptance still needed.** The release workflow pins
Qt 5.15.2/MinGW 8.1; product CI uses Qt 6.10.2/MinGW 13.1. README badges, issues and
release links point upstream, while issues are disabled on this fork. The current
queue largely contains hardening and plumbing, not a dated user acceptance
milestone. **Fix:** define one usable Windows dogfood milestone and a support
destination; prove open/play/scrub/export/reopen on the candidate package. The
machine's available clips and Qt toolchain permit preparation without waiting for
the remote GPU host.

## What should not be restarted

- The headless CDNG/receipt work and rendered export already have implementations.
  Verify their present scope before writing replacement feature cards.
- The old “CURRENT REGRESSION” aspect note is not current proof: MainWindow now
  passes `mainWindowGpuTexturePresentDisplaySize(..., task.stretchX, task.stretchY)`
  to the window presenter (`MainWindow.cpp:5073–5094`). Verify all paths and images;
  do not blindly reapply the historical patch.
- Existing golden provenance, byte/pixel checks, explicit fallbacks, hash-locked
  dependencies, ownership safeguards and bounded process tools are assets to keep.
- Do not restart the ratification program, replace the bridge, implement Vulkan/
  Metal, or drain every historical branch as prerequisites for the first product
  delivery. Any applicable current gate still needs a legitimate resolution.

The durable change is to make the next action and its acceptance mechanically
decidable. The implementation sequence below reuses the recovery already landed
and confines new factory work to a named product blocker.
